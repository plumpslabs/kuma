# Kuma — Core Workflow & Architecture

> **One sentence:** Kuma is a *shadow memory system* that injects the answer to
> *"where is this file fragile & why"* right before the agent touches it — not a
> dashboard that shows everything it remembers.

---

## 1. Philosophy

- **Kuma is not a database.** The SQLite graph is a *derived cache* — code is the
  source of truth, Kuma just remembers what you already learned.
- **Memory is recorded only when it pays back.** Gotchas, decisions, and
  architecture flows — not every symbol or edge.
- **Inject before edit, not on demand.** The hooks deliver context with zero
  extra agent steps. On-demand tools (`history`, `flow`) are fallbacks.
- **No gimmicks.** Anything a native tool (grep/glob) does faster was removed.

---

## 2. Per-Project Context Model

Kuma stores all context locally in `.kuma/`:

```
.kuma/
├── kuma.db          # SQLite knowledge graph (WASM) — nodes, edges, research cache, changes
├── init.md          # Project behavioral rules (generated by `kuma init`)
├── memory.json      # Session state + metrics (auto)
├── auto-gotcha.json # Self-learning loop state (auto)
├── policy.yml       # OPTIONAL safety policy — only read if you create it
├── memories/        # Decision log markdown (decisions.md)
├── checkpoints/     # Atomic snapshots (label/ with kuma.db + files/)
```

**Facts that matter:**

- **Research cache is NOT a folder** — it lives in the `research_cache` table
  inside `kuma.db`. (Older docs referenced `.kuma/research/<scope>.json`; that
  was wrong and has been corrected.)
- **Hooks are NOT stored under `.kuma/`** — they are registered in
  `.claude/settings.json` (PreToolUse) as `kuma hook pre-edit` / `pre-bash`.
- **`policy.yml` is optional** — only read if you create it. It's enforced by
  `guard`/`check` via the safety proxy.
- **`checkpoints/` is created on demand** by `kuma_safety({ action: "checkpoint" })`
  — each snapshot is `<label>/` containing a copy of `kuma.db` + `files/` +
  `manifest.json`.

## 3. Tools & Actions (13 core actions, 0 gimmicks)

### `kuma_context` — understand before you change
`init` · `research` · `history`

### `kuma_memory` — record what pays back
`gotcha` · `decision` · `arch_flow` · `research_save`

### `kuma_safety` — when risky
`guard` · `verify` · `checkpoint` · `rollback_label`

## 4. Core Workflow

```
START SESSION
  │
  1. init                    ← lean brief + session restore (<500 tokens)
  │
  DURING EDITS (auto — zero effort)
  ├─ pre-edit / pre-bash hooks  ← inject gotchas + decisions + history
  │    • freshness: gotchas validated via content hash (stale excluded)
  │    • dedupe: same file not re-injected within 15 min
  │    • budget: max ~400 tokens per inject
  │    • loop capture: 4+ edits/30 min → low-severity auto-gotcha
  │    • verify hint: suggests kuma_safety verify after editing gotcha'd files
  │
  WHEN DISCOVERING
  ├─ gotcha   ← bug/quirk found? record immediately
  ├─ decision ← chose between options? preserve rationale
  ├─ arch_flow← traced a complete flow? (max 5 core files)
  ├─ research_save ← explored an area? cache the findings
  │
  AFTER WORK
  └─ verify   ← scoped tests + AST validation
```

---

## 5. North Star Metric

> **"Shadow memory saved X minutes"** — derived from injection count × estimated
> re-research time per injection. Visible in the Studio dashboard (humans only;
> agents never call the Studio).

The system is working when an agent edits a fragile file it has **never seen
before** and the gotchas are already there — no manual `history` call needed.
